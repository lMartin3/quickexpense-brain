# 9.1 Técnica

> [!quote] Consigna
> En él se revisan aspectos relativos al hardware, software y telecomunicaciones y aquellos referidos a la cantidad y capacitación del personal.
> En caso de ser insuficiente el parque tecnológico y requiera de su ampliación, la misma debe estar detallada en este punto y deberá ser considerada en el momento de realizar el estudio de viabilidad económica ya que pasa a formar parte de la inversión necesaria para que el sistema pueda funcionar adecuadamente. Dentro de este estudio se incluye el nivel de capacitación del personal que utilizará el sistema.
> Características del estudio de viabilidad técnica:
> - Análisis del parque instalado (de acuerdo con los datos recogidos en el relevamiento detallado)
> - Determinación de necesidad de actualización, mejora o ampliación del parque instalado con el detalle de que se debe incorporar.
> - Grado de necesidad de capacitación de los usuarios.
> - Requerimientos de instalaciones (redes, telecomunicaciones, adecuaciones de los ámbitos de trabajo, etc.) considerados necesarios para la implementación del sistema.

Viabilidad técnica: hardware, software, telecomunicaciones, personal y capacitación. Lo que haya que comprar pasa a [[8.3 Modelo de inversión]].

## Respuesta

<!-- Todo lo que esté debajo de este título es el texto que se compila al documento final. -->

El proyecto es técnicamente factible: la base funcional de la aplicación ya está desarrollada y en uso por el autor, la tecnología necesaria está disponible como servicio y el fundador tiene la formación y la experiencia necesarias para completarla.

**Estado actual.** Ya están implementados el registro de cuentas, movimientos y categorías, tanto desde la aplicación web como desde el asistente de Telegram; el procesamiento de mensajes de texto, audios y documentos PDF; los espacios de trabajo compartidos con roles; la evolución de los saldos y las cuentas en distintas monedas. Las funciones restantes de la versión Alpha y del lanzamiento se detallan en el punto 5.2.

**Software.**

| Componente | Tecnología |
| ------------------------------- | ------------------------------------------------------------ |
| Servidor de aplicación (*backend*) | Kotlin sobre Spring Boot, con arquitectura de monolito modular en capas (dominio, aplicación e infraestructura) |
| Aplicación web (*frontend*) | Next.js y React, con TypeScript; instalable como PWA |
| Base de datos | PostgreSQL, con seguridad a nivel de fila para aislar los datos de cada espacio de trabajo |
| Autenticación | Keycloak, servidor de identidad con inicio de sesión unificado, autoalojado |
| Archivos adjuntos | RustFS, almacenamiento de objetos compatible con S3, autoalojado |
| Inteligencia artificial | Claude Haiku 5.5 para los mensajes habituales, Claude Sonnet 5.5 para las conciliaciones y las operaciones complejas, TypeSafe Jev para decisiones menores y OpenAI Whisper para la transcripción de audios. El asistente opera mediante *tool calling* |
| Mensajería | API de bots de Telegram y WhatsApp Business Platform |
| Datos externos | Índice de precios al consumidor del INDEC y cotizaciones del dólar de DolarHoy, obtenidas leyendo el sitio mediante un *crawler*, ya que no ofrece una API pública |

Todas las herramientas de desarrollo son de código abierto o gratuitas, por lo que no hay que comprar licencias.

**Hardware e infraestructura.** No se compra hardware. El sistema funciona en un **servidor dedicado alquilado**, con un costo de alrededor de USD 30 por mes (ver 8.2), en el que se ejecuta toda la cadena de software en contenedores Docker: la aplicación, la base de datos, el servidor de identidad y el almacenamiento de archivos. Solo los modelos de IA, la mensajería y las fuentes de datos externas son servicios de terceros. El código se versiona en GitHub y cada cambio se compila, se prueba y se despliega automáticamente mediante GitHub Actions. El desarrollo se realiza con el equipo informático del fundador.

**Telecomunicaciones.** El servicio solo requiere la conexión a internet del servidor y de los usuarios. La comunicación con los proveedores de IA, las plataformas de mensajería y las fuentes de datos se realiza mediante sus interfaces de programación (APIs).

**Personal y capacitación.** El desarrollo y la operación están a cargo del fundador, con formación en ingeniería en sistemas y experiencia profesional en desarrollo de software para el sector financiero (ver 7.2). Los usuarios no requieren capacitación: interactúan con el asistente en lenguaje natural y la aplicación web sigue convenciones habituales.

**Riesgos técnicos.**

- **Dependencia de proveedores de IA.** Los modelos son servicios de terceros cuyo precio y disponibilidad pueden cambiar. La integración mediante una capa de abstracción permite reemplazar un modelo por otro. TypeSafe Jev se encuentra en acceso anticipado [@aiweekly2026jev]; si no estuviera disponible, esas decisiones las tomaría Claude Haiku 5.5.
- **Dependencia de las plataformas de mensajería.** La integración de mensajería está abstraída en el código, lo que facilita sumar o reemplazar canales. La incorporación de WhatsApp está prevista para el lanzamiento.
- **Lectura de las cotizaciones.** Como DolarHoy no ofrece una API, un cambio en la estructura de su sitio puede interrumpir la lectura de las cotizaciones. Como alternativa, el Banco Central publica el tipo de cambio oficial mediante una API pública.
- **Capacidad de un único servidor.** Es suficiente para la escala prevista en el horizonte; si la demanda la superara, se contrataría un servidor de mayor capacidad.
